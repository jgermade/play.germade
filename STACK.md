# Stack

- **UI:** [jq79](https://github.com/jgermade/jq79) single-file `.html` components, from npm (pinned), bundled by **Vite** with `jq79/vite`.
- **PWA:** `vite-plugin-pwa` (`injectManifest`), own service worker in `src/sw.js` (Workbox): precached shell, engines and covers cached on first use, COOP/COEP added to navigations.
- **Engines:** the wasm-gaming engines, each an independent repo implementing `@wasm-gaming/engine-specs`. Pinned in `src/lib/engines.json`, fetched from each engine's GitHub Release into `public/engines/<id>/` by `scripts/fetch-engines.mjs`. Never built here.
- **Storage:** OPFS. Each engine owns `<engine-id>/`; the launcher uses the game slug as namespace → `<engine-id>/<slug>/` holds the installed data and the saves.
- **Routes:** one page per catalog entry (`/sonic1/`, `/megadrive/?game=…`), generated by `scripts/routes-plugin.mjs`; each mounts the engine's app or the generic one (`src/route/`).
- **Tests:** `node --test tests/` (catalog integrity).
- **Layers** (`src/`), the owner's structure for every front end; `tests/layers.test.mjs` fails on an import that crosses them:
  - `helpers/`: functions with no dependencies and no memory, with their tests (patches, zip, header identification in `helpers/systems/`, rom-manager's naming rules in `helpers/rom-manager/`). They import helpers only.
  - `components/`: no memory, no dependencies but helpers (`Hero`, `Notice`, `InstallDialog`, `PauseMenu`).
  - `lib/`: services, stores and data (`storage`, `library`, `rom-library`, `dat`, `input`, `touch`, `drop-guard`, `catalog.js`, `engines.json`, `datasets.json`). They import helpers and lib.
  - `views/`: put it all together (`App`, `RomDrawer`, `Route`, `generic-app`).
  - Entries stay at the top: `main.js`, `route/main.js`, `sw.js`.
