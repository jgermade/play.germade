# BlastEm integration & Emulator Core Selection

- **Date:** 2026-07-09 00:16
- **Status:** Completed

## Goal

Add **BlastEm** (a highly accurate Sega Genesis / Mega Drive emulator) as an alternative core to **JGenesis**.
Implement a settings toggle or selector in the launcher UI to allow the user to choose which emulator core (JGenesis or BlastEm) to use for launching Sega Genesis games.

## Research & Plan

1. **BlastEm WASM build:**
   - Investigate how to build or obtain a WebAssembly port of BlastEm.
   - BlastEm has a libretro core and some standalone WASM ports. We need to determine the best approach (similar to how we compile JGenesis via Docker).
2. **Settings UI:**
   - Add a settings panel or a configuration toggle to the Astro launcher.
   - The user preference can be stored in `localStorage` (e.g. `preferredGenesisCore = 'jgenesis' | 'blastem'`).
3. **Launcher Integration:**
   - Update `src/data/games.ts` or the routing logic so that launching a Sega Genesis game routes the user to the appropriately selected emulator core's wrapper (`/console/blastem/` vs `/console/jgenesis/`).
   - Alternatively, pass the core choice as a URL parameter to a unified Genesis launcher page.

## Implementation Details

### 1. Settings UI (ESC Menu)
- **Location:** We will inject a dropdown/toggle for **"Emulator Core"** at the very top of the `#jgenesis-config` (and the corresponding BlastEm settings) panel within the ESC menu.
- **Options:** `JGenesis` (Default) and `BlastEm`.
- **Functionality:** 
  - Changing the core saves the choice to `localStorage.getItem('preferredGenesisCore')`.
  - It then immediately redirects the browser to the respective path (e.g. `/console/blastem/` or `/console/jgenesis/`).
  - The options displayed below the core selection will be specific to the selected engine (JGenesis settings for JGenesis, and BlastEm settings for BlastEm).
- **ROM Selection:** The ROM gallery is already integrated into the ESC menu. Selecting a ROM will load it directly into the currently active core.

### 2. Game Launch Routing (Launcher)
- In `src/pages/index.astro`, we will intercept the "Play" button for the Sega Megadrive console.
- Before routing, we will check `localStorage.getItem('preferredGenesisCore')`. If `blastem`, route to `/console/blastem/`, otherwise `/console/jgenesis/`.

### 3. BlastEm Build Pipeline
Create `scripts/blastem/build-blastem-docker.sh`.
- The official BlastEm source is hosted on Mercurial.
- The script will run a Docker container based on `emscripten/emsdk:latest`. 
- Inside the container, it will:
  1. `sudo apt-get update && sudo apt-get install -y mercurial`
  2. `hg clone https://www.retrodev.com/repos/blastem/ /workspace/blastem`
  3. Run `make OS=web` (or the equivalent Emscripten target for BlastEm).
  4. Extract the WASM and JS outputs.
- Output these to `public/console/blastem/`.

### 4. BlastEm Frontend Shell
Create `scripts/blastem/index.html`.
- Custom shell identical in structure to our JGenesis integration.
- It will include the `launcher-overlay.js` for the ESC menu, the ROM gallery, and the specific BlastEm settings.

### Update 6
- Discovered and fixed a critical bug in ALL build scripts (including `build-blastem-docker.sh`). Because the scripts were moved one directory deeper into `scripts/engines/<engine>/` in an earlier session, the `ROOT_DIR` variable was incorrectly resolving to `scripts/` instead of the project root.
- As a result, the compilation artifacts for BlastEm (and potentially others) were being written to a mistakenly created `scripts/public/` directory instead of the actual `public/` directory. The browser was loading a very old, cached build!
- Cleaned up the erroneous directories and fixed the path resolution in all engine build scripts. A full rebuild of BlastEm with the font fix is currently running and deploying to the correct path.

### Update 7
- Fixed `Aborted(Assertion failed: config->size > 0.0f)` error in BlastEm's Nuklear UI. This was caused by the dynamically created `canvas` not having an explicit width and height set before initialization, causing Emscripten/SDL to report a 0x0 window size, which led to a 0.0f font size calculation.
- Explicitly set `canvas.width = 640` and `canvas.height = 480` in `index.html` before passing it to the BlastEm WASM Module.

### Update 8
- Even though the `canvas.width` was hardcoded, Emscripten's SDL2 implementation was still getting a 0x0 size via `getBoundingClientRect()` because the parent `#jgenesis` element had `display: none` (via the `.hidden` class).
- Modified the CSS for `#jgenesis.hidden` to use `visibility: hidden` and off-screen absolute positioning (`top: -10000px`) instead of `display: none`. This ensures the DOM retains its layout dimensions and SDL successfully detects the 100vw x 100vh window size during initialization, preventing the Nuklear UI font crash.
