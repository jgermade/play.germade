# jgenesis integration — Megadrive/Genesis emulator (multi-system: SMS, NES, SNES future)

- **Date:** 2026-07-06 01:15
- **Status:** In Progress

## Goal

Add **jgenesis** to the launcher as the Megadrive/Genesis emulator core,
replacing the current `megadrive-emu` WIP placeholder in `src/data/games.ts`.
jgenesis is a multi-system emulator (Rust-based, by jsgroth) that supports
Sega Megadrive/Genesis now, with SMS, NES, SNES, GBA, 32X and Sega CD as
future expansion targets — all from a single WASM-compiled core.

## User decisions (2026-07-06 01:19)

1. **Project**: `jsgroth/jgenesis` (https://github.com/jsgroth/jgenesis)
2. **Build**: Use prebuilt if available; otherwise compile from source.
3. **ROMs**: ROM list from directory `public/console/genesis/`.
4. **URL**: Megadrive served at `/console/megadrive` (future: `/console/snes`,
   `/console/nes`, etc.).
5. **Category**: "Consolas Retro".

## Research findings (2026-07-06)

- **jgenesis** (https://github.com/jsgroth/jgenesis) is a multi-system
  emulator written in Rust. It supports: Megadrive/Genesis, SMS/GG, SNES,
  GBA, 32X, Sega CD — all in one codebase.
- **No prebuilt web release exists**: GitHub releases (v0.13.1) only include
  Windows and Linux desktop builds (CLI + GUI). Must compile from source.
- **`frontend/jgenesis-web/`** is a dedicated WASM web frontend:
  - Build: `rustup run nightly wasm-pack build --target web . -- -Z build-std=panic_abort,std`
  - Requires **Rust nightly** + `rust-src` component (audio worklet needs
    shared memory between main thread and audio worklet → rebuild std with
    atomics support).
  - Requires **wasm-pack** (`cargo install wasm-pack`).
  - Output: `pkg/` directory (WASM + JS glue), plus `index.html` and `js/`
    (audio-processor.js, idb.js, polyfill.js, ui.js).
  - Rendering: **WebGPU** (wgpu) — requires a WebGPU-capable browser
    (Chrome/Edge 113+, not Safari/Firefox stable yet).
  - Windowing: winit (wasm target).
  - Audio: AudioWorklet (`js/audio-processor.js`).
  - ROM loading: rfd (Rust File Dialog) → browser file picker.
  - Saves: IndexedDB (`js/idb.js`).
  - Config UI: full settings panel in `index.html` (image filtering, blend
    shaders, per-system config: aspect ratio, CPU speed, sprite limits,
    audio filters, etc.).
  - **HTTP headers required**: `Cross-Origin-Opener-Policy: same-origin` +
    `Cross-Origin-Embedder-Policy: require-corp` — **already set** in
    `astro.config.mjs` (using `credentialless` which is compatible).
- **COOP/COEP already configured**: `astro.config.mjs` sets
  `Cross-Origin-Opener-Policy: same-origin` and
  `Cross-Origin-Embedder-Policy: credentialless` on the dev server.
  Production deploy must also set these headers.
- **Launcher routing**: currently links to `/game/${slug}/index.html`.
  jgenesis breaks this pattern — it lives at `/console/megadrive/`. The
  launcher `index.astro` hardcodes `/game/${game.slug}/index.html` in the
  Play button onclick; needs to be made configurable per-game (e.g. a
  `url` field in `GameEntry`, or a `urlPath` property).

## Risks / unknowns

- **WebGPU requirement**: jgenesis-web uses wgpu (WebGPU), not WebGL. This
  limits browser support (Chrome/Edge only for now). No fallback.
- **Rust nightly + build-std**: the build is more complex than the
  Emscripten Docker builds. Need a Docker image with Rust nightly +
  wasm-pack + rust-src. May need a custom Dockerfile.
- **Headless testing**: Playwright/Chromium headless may not support
  WebGPU. Verification might need a headed browser or
  `--enable-unsafe-webgpu` flag.
- **Gamepad support**: winit's wasm gamepad API may or may not work
  out-of-the-box. If not, we may need to patch jgenesis-web or inject our
  own gamepad→keyboard translator (but jgenesis doesn't use SDL2
  keyboard — it uses winit events directly, so keyboard injection won't
  work the same way as the Sonic games).
- **ROM loading bypass**: upstream uses rfd (file picker). We need to
  load ROMs from a URL instead. This requires either patching the Rust
  code or finding the JS-side `channel` API to feed ROM bytes directly.

## Extension (2026-07-06 02:15) — Per-console ROM organization

### Problem

ROMs are currently stored flat in `public/roms/` with a single
`roms.json` manifest. As jgenesis supports multiple consoles (SNES,
NES, GBA, SMS, etc.), this doesn't scale — ROMs need to be organized
per-console and manifests should be per-console too.

### Plan

1. **ROM directory structure**: Move ROMs into per-console subdirectories:
   - `public/roms/megadrive/` — Megadrive/Genesis ROMs (.md, .gen, .bin, .smd)
   - `public/roms/snes/` — SNES ROMs (.sfc, .smc)
   - (future: `public/roms/nes/`, `public/roms/gba/`, etc.)

2. **Per-console manifests**: Instead of a single `roms.json`, generate
   one manifest per console: `roms.megadrive.json`, `roms.snes.json`,
   etc. These live at `public/roms/roms.<console>.json` (single place
   to find all manifests). URLs inside point to
   `/roms/<console>/<filename>`.

3. **Generator script rewrite**: `generate-roms-manifest.py` now takes
   `<roms-root>` (e.g. `public/roms`), scans each subdirectory as a
   console, and generates `roms.<console>.json` for each.

4. **Consumers updated**:
   - `build-jgenesis-docker.sh`: generator call unchanged (passes
     `public/roms`).
   - `scripts/jgenesis/index.html`: fetches `/roms/roms.megadrive.json`
     (via a `CONSOLE` JS variable for future per-console pages).
   - `.gitignore`: adjusted for new directory structure.

5. **Migration**: Move existing 6 Megadrive ROMs from `public/roms/` to
   `public/roms/megadrive/`. Delete old `public/roms/roms.json`.
   Create `public/roms/snes/.gitkeep` for future SNES ROMs.

## Extension (2026-07-06 03:07) — Fix ROM list visibility and hide default Open ROM button
