# Sonic CD integration (RSDKv3 → WASM)

- **Date:** 2026-07-05 21h00
- **Status:** Completed

## Goal

Add **Sonic CD** to the launcher, compiled to WASM like Sonic 1/2. Sonic CD's
2011 remaster runs on **RSDKv3** (`Rubberduckycooly/Sonic-CD-11-Decompilation`),
the direct predecessor of the RSDKv4 engine we already ship for Sonic 1/2 —
same architecture (SDL2, `Data.rsdk`, `settings.ini`, native Escape Dev Menu),
so the integration should mirror `scripts/sonic/` closely.

## Proposed plan

### 1. Assets — `game-assets/sonic-cd/`
- `Data.rsdk` from the Sonic CD 2011 release (Steam/mobile/Origins), provided
  by the user (not committed; same policy as the other games).
- `videos/` (FMV `.ogv` files) is optional in the decomp — propose skipping
  FMVs for the first pass (engine falls back gracefully when they're missing);
  can be revisited later.

### 2. Build — `scripts/sonic-cd/build-sonic-cd-docker.sh`
Modeled on `scripts/sonic/build-sonic-docker.sh`:
- Clone upstream `Rubberduckycooly/Sonic-CD-11-Decompilation` (fresh clone,
  patches applied by the script at build time — same convention as Mania).
- Unlike Sonic 1/2 (which used the `mattConn` WASM fork), no maintained WASM
  fork exists for RSDKv3, so the script generates its own Emscripten build
  (Makefile or direct `emcc` invocation inside `emscripten/emsdk:latest`
  Docker), porting the known-good flags from the Sonic 1/2 build:
  `TOTAL_MEMORY=256MB`, `STACK_SIZE=5MB`, `--preload-file Data.rsdk
  --preload-file settings.ini`, output as `index.js` (custom HTML shell).
- Port the same patch set that RSDKv4 needed (RSDKv3's code is near-identical
  in these areas):
  - `main.cpp`: `emscripten_set_main_loop` with lazy `Engine.Init()` inside
    the loop callback (init-order fix);
  - `Audio.cpp`: explicit `SDL_InitSubSystem(SDL_INIT_AUDIO)` before
    `SDL_OpenAudioDevice`;
  - `Input.cpp`: continuous controller init with fallback "Web Gamepad"
    mapping in `ProcessInput()`;
  - `WebDevMenu.cpp` (embind): `web_devmenu_get_stage_list` /
    `web_devmenu_load_stage` / `web_devmenu_set_paused`, adapted to RSDKv3's
    globals (verify names against RSDKv3's `Debug.cpp`/`RetroEngine.hpp`
    during implementation — e.g. lamp/star post globals are Sonic 1/2
    specific and drop out; Sonic CD uses its own time-travel/checkpoint
    globals if any are needed).
- If RSDKv3 hits wasm `call_indirect` signature traps like Mania did, fix the
  mismatched signatures at the source (per the previous session's approach) —
  **not** with `EMULATE_FUNCTION_POINTER_CASTS`. RSDKv3 scripts are
  bytecode-interpreted like v4, so this is unlikely to be needed.

### 3. Settings — `scripts/sonic-cd/settings-sonic-cd.ini`
Based on `settings-sonic-{1,2}.ini`: `DevMenu=false`, windowed defaults,
starting scene pointed at the normal boot sequence.

### 4. HTML shell — `scripts/sonic-cd/index.html`
Copy of `scripts/sonic/index.html` adapted for the game:
- `window.__gamepadKeyMap = 'rsdkv4'` + `/shared/game-input.js` (RSDKv3 uses
  the same default keyboard binds as v4 — verify against RSDKv3's
  `ReadSaveRAMData`/input defaults during implementation, adjust the preset
  or pass a custom map if they differ);
- `/shared/launcher-overlay.js` with the web Dev Menu overlay (same
  Escape-interception + `web_devmenu_*` embind bridge as Sonic 1/2), and
  `window.__hideLauncherReturnButton = true`.

### 5. Wiring
- `Makefile`: `build.sonic-cd` target.
- `src/data/games.ts`: new `sonic-cd` entry (slug `sonic-cd`, status `ready`
  once verified; cover art TBD — reuse `sonic_cover.png` initially).
- Output deployed to `public/game/sonic-cd/`.

### 6. Verification
- Docker build from fresh clone exits 0.
- Headless Chromium (Playwright): boot → SEGA logo → title screen →
  Palmtree Panic Zone gameplay with sustained input; check for
  `call_indirect` traps, audio start after user gesture, gamepad translator
  (fake pad injection) — same test recipe as the Mania perf session.

## 2026-07-05 21:50 - Build Success and Frontend Integration

- Successfully compiled the WebAssembly module (`index.js` / `index.wasm`) for Sonic CD (RSDKv3).
- Added `libtheora` and `tinyxml2` as vendored dependencies in the build script to resolve linking errors.
- Handled legacy OpenGL translation issues (glScalef, glColorPointer) by applying Emscripten's `LEGACY_GL_EMULATION=1` flag and `-lGL` to compile the fixed pipeline functions RSDKv3 requires.
- Updated `RetroEngine.hpp` to fully support `__EMSCRIPTEN__` and correctly assign `RETRO_STANDARD` as the platform ID so the runtime finds its initialization pathways.
- The build is now outputting cleanly to `public/game/sonic-cd` alongside the `Data.rsdk` file.

## 2026-07-05 21:55 - Fix Emscripten GL Crash

- Fixed runtime crash `The provided ArrayBuffer value must not be resizable` by removing `ALLOW_MEMORY_GROWTH=1` from Emscripten link flags, resolving compatibility issues with `TextDecoder` and `WebGL` on newer V8 engines.
- Fixed `DrawElements doesn't actually prepareClientAttributes properly` crash in `Drawing.cpp` by entirely disabling OpenGL for Emscripten (`RETRO_USING_OPENGL=0`). RSDKv3 now correctly falls back to its robust software rasterizer drawing to a hardware SDL2 texture, which Emscripten transparently accelerates via WebGL 2D backend without legacy GL emulation bugs.

## 2026-07-05 22:20 - Debug URL Flag (`rAF=60fps`)

Added an optional fallback mechanism directly into the `index.html` wrapper of the games. By adding `?rAF=60fps` to the URL, the browser's native `requestAnimationFrame` is polyfilled with a 60fps `setTimeout` loop. This bypasses VSync entirely and forces the WebGL canvas to refresh exactly 60 times a second. While not recommended for normal play due to potential micro-stuttering, it acts as a very useful debugging flag for performance testing and QA.
