# Super Mario World widescreen — Phase 2 (wire ExtendedAspectRatio)

- **Date:** 2026-07-06 00:45
- **Status:** In Progress

## Goal

Phase 2 of the SMW integration, per the plan approved in
`2026-07-05_23h56.smw-widescreen-integration.session.md` (user: "adelante con
la fase 2"). Scope for this session: **steps 1–2** of the Phase 2 plan —
playable widescreen with known sprite pop-in at the old 256px edges. The
wide-snes game-logic patch checklist (step 3) is burned down in later
sessions.

## Plan (from the approved Phase 1 session, restated)

1. **Wire the dormant plumbing** (build-time patches, upstream-shaped):
   - Parse `ExtendedAspectRatio = W:H` in `src/config.c` →
     `g_config.extended_aspect_ratio` (any ratio; extra side pixels computed
     as `(224 * W/H * 8/7 - 256) / 2`, clamped/rounded like zelda3).
   - Assign `ppu->extraLeftRight` at PPU init/reset so the LakeSnes PPU
     renders the extra side columns.
   - Scale the hardcoded 256px render path with `g_snes_width`:
     `g_pixels`/`g_my_pixels` buffers, `PpuBeginDrawing(..., 256*4, ...)`
     pitch, SDL texture/window sizing.
2. **HTML shell**: `?aspect=W:H` query param — a `Module.preRun` hook
   rewrites the `ExtendedAspectRatio` line of `smw.ini` in MEMFS before
   `main()` runs, so one build serves every ratio. Default **16:9**;
   `?aspect=4:3` gives vanilla. Canvas CSS `aspect-ratio` updated to match.
3. **Verification** (headless Chromium, Playwright): boot to gameplay in
   both 4:3 and 16:9; screenshots side by side in a horizontal level;
   confirm BG layers extend across the full width; note (expected, accepted
   for now) sprite pop-in at the old edges.

## Constraints

- All patches keyed on `g_config.extended_aspect_ratio` — never a
  hard-coded 352 — so any ratio up to ~21:9 works.
- Patches are applied at build time by `scripts/smario-world/`
  patch scripts against a fresh `snesrev/smw` clone (same model as Phase 1);
  every anchor must assert exactly one match.
- Title screen / overworld / credits may remain effectively 4:3 (rendered
  wide but with vanilla logic), as wide-snes itself pillarboxes them.

## 2026-07-06 04:45 - Steps 1–2 implemented and verified

New build-time patch `scripts/smario-world/patch-smw-widescreen.py`
(anchored replaces, applied after the emscripten patch; both orders tested):

- `src/snes/ppu.h` — `kPpuExtraLeftRight` 0 → 96 (18:9 max, same as
  zelda3), `kPpuXPixels` derived from it; new `Ppu.renderFlags` field.
- `src/snes/ppu.c` — `PpuBeginDrawing` used to **discard** its
  `render_flags` argument (that is why smw's existing `NoSpriteLimits` ini
  key was dead in the new PPU): now stored. `ppu_evaluateSprites` culling
  extended from the vanilla 0..256 window to the extra side region
  (zelda3-style: wrap-to-negative at `256+extra`, x-range and per-tile
  fetch bounds widened), and the 32-sprite/34-tile per-line limits honor
  `kPpuRenderFlags_NoSpriteLimits` — important in widescreen, where more
  sprites are in range per line and the stock limits would cause dropout
  that 4:3 never showed.
- `src/config.c` — parses `ExtendedAspectRatio = W:H` ([Graphics]).
  **Formula deviation from the Phase 1 design note**: zelda3 uses square
  pixels (no 8/7 PAR correction), so `extra = (224*W/H − 256)/2` per side;
  16:9 → 71 (398×224), not the ~336–352px the note estimated with PAR.
  This matches the Phase 1 shell, which already displays square pixels
  (`aspect-ratio: 8/7`). "4:3" is treated as vanilla 256×224 (zelda3
  semantics; "8:7" also computes to 0). Clamped to `kPpuExtraLeftRight`.
- `src/main.c` — `g_pixels`/`g_my_pixels` sized for the max width;
  `PpuBeginDrawing` with `g_snes_width*4` pitch and the real render flags;
  `RtlDrawPpuFrame` copies `g_snes_width`-wide rows and refreshes
  `extraLeftRight/extraLeftCur/extraRightCur` on both PPUs **every frame**
  (`ppu_reset` zeroes them on game reset, `ppu_copy` clobbers them on
  savestate load). No per-frame `PpuSetExtraSideSpace` clamping yet — the
  game logic is unpatched, full extent always renders.

Shell/config wiring:

- `smw.ini`: `ExtendedAspectRatio = 16:9` (new default).
- `index.html`: `?aspect=W:H` parsed via `URLSearchParams` (a first regex
  on `location.search` missed `%3A`-encoded colons), mirroring config.c's
  integer math exactly; sets `--snes-w` CSS var (canvas `aspect-ratio` +
  definite width) and rewrites the `ExtendedAspectRatio` line of the MEMFS
  `smw.ini` in `Module.onRuntimeInitialized` — which fires after all run
  dependencies (preloaded data) resolve and before `main()`.
- `build-smw-docker.sh` runs the new patch script.
