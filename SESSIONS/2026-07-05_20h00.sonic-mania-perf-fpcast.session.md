# Sonic Mania WASM perf: remove EMULATE_FUNCTION_POINTER_CASTS

## Why

Sonic Mania (RSDKv5U) ran noticeably worse in the browser than Sonic 1/2
(RSDKv4). The dominant self-inflicted cost was the
`-sEMULATE_FUNCTION_POINTER_CASTS=1` link flag added during the Mania
integration (see `2026-07-05_05h00.sonic-mania-integration.session.md`). That
flag was a blunt fix for wasm `call_indirect` "function signature mismatch"
traps that only reproduce once you enter a zone: it routes **every** indirect
call in the whole program through a runtime-adapting `fpcast-emu` thunk. RSDKv5's
object system dispatches Update/LateUpdate/StaticUpdate/Draw for every entity
every frame through function-pointer tables, so this taxed the hottest path in
the engine.

## What was actually mismatched

Rather than emulate, the real mismatches were found and fixed at the source. A
static sweep (scripts kept in scratch during the session) covered:
- all `(Type_StateMachine)` casts + `CREATE_ENTITY` data-smuggled states,
- `CutsceneSeq_StartSequence` variadic state tables,
- a `clang -fsyntax-only -Wincompatible-function-pointer-types` pass over
  `SonicMania/Objects/All.c` + `Game.c`,
- a **slot-by-slot signature diff** of the three engine↔game function tables:
  the engine's fill order in `RSDKv5/RSDK/Core/Link.cpp` (RSDK + API tables) and
  `ModAPI.cpp` (Mod table) vs. the game's `SonicMania/GameLink.h` struct decls,
  under this build's preprocessor context (REV0U, mod loader v2, MANIA_USE_PLUS,
  GAME_INCLUDE_EDITOR, RETRO_EMSCRIPTEN).

Findings (all now patched by the build script, against a fresh clone):
1. `GameLink.h` API table: `TryAuth`, `TryInitStorage` declared returning
   `void` but engine returns `int32`; `LoadUserFile`/`SaveUserFile`/
   `DeleteUserFile` declared `void` but engine returns `bool32`. These fire
   during menu + save-init — exactly where gameplay crashed. Also
   `SetScreenSize` declared `int32`-returning vs engine `void` (no caller today,
   fixed for truthfulness).
2. `CPZBoss.c`: parks its state pointer at `CPZBoss_CheckMatchReset`, which
   returns `bool32`, but states run through `void(*)(void)`. Added a
   correctly-typed `CPZBoss_State_CheckMatchReset` wrapper.
3. `GHZCutsceneK.c/.h`: `GHZCutsceneK_Cutscene_None` declared `(void)` but
   cutscene states are `bool32(*)(EntityCutsceneSeq *)`. Added the host param.

The Mod table diff came back clean once raw `void*` slots were accounted for;
the RSDK table's only real diffs were `SetScreenSize`/`LoadPalette` — LoadPalette
is a false positive (engine really is 5-arg; game decl matches at wasm level).

## Change

`scripts/sonic-mania/build-sonic-mania-docker.sh`:
- New "Patch function-pointer signature mismatches" step (python, patches the
  fresh clone's GameLink.h + CPZBoss + GHZCutsceneK).
- `Emscripten.cmake` link options: **removed** `-sEMULATE_FUNCTION_POINTER_CASTS=1`
  and `-sBINARYEN_EXTRA_PASSES=pass-arg=max-func-params@17`; **added** `-O3` at
  link (Release only optimizes compile lines, emcc link stage was -O0).

## Verification

Rebuilt via Docker from a fresh clone (clean build, exit 0). Drove headless
Chromium (Playwright) boot → menus → **Studiopolis Zone gameplay** with sustained
input, plus attract demo + pause. No `RuntimeError: function signature mismatch`
/ null-function / abort across any route. This is past the exact point the old
build trapped.

- `.wasm` shrank 6,288,938 → 4,847,667 bytes (−23%), since the fpcast-emu thunks
  and their extra binaryen pass are gone.

## Notes / follow-ups not done

- Still WebGL1 + wasm32 software-rendered (fine; not the bottleneck). Next
  perf levers if wanted: profile software-blit vs entity-update loop; consider a
  GL render path. Music/vorbis still decodes on the main thread (no -pthread).
- Only `build-sonic-mania-docker.sh` changed in the repo; the C patches live in
  that script and apply at build time (consistent with how the other RSDK
  patches in this repo are handled).

## Extension — 2026-07-05 20h26: Sonic Mania gamepad fix + shared game-input.js

New topic appended to the in-progress session (per convention: no new session
file without explicit capitulation).

### Why

Gamepad input never reached Sonic Mania. The SDL2 gamepad proxy added in
commit `c7aa714` (forces `mapping: "standard"` + synthetic `gamepadconnected`)
was not enough on its own — same story as Sonic 1/2, where the fix that
actually worked was the **gamepad→keyboard translator** that synthesizes
KeyboardEvents for the engine's default key bindings, bypassing SDL2's
gamepad path entirely.

Sonic 1/2 and Mania also had near-identical inline copies of the
AudioContext autoplay-unlock (`resumeAudio`) and the SDL2 proxy in their
`index.html` shells — duplicated code that was drifting (the Mania copy of
`resumeAudio` had already lost its `audioResumed = true` line in the resolved
promise).

### What changed

- **New `public/shared/game-input.js`** (loaded synchronously *before* the
  engine script, like `launcher-overlay.js` but not deferred, since its
  `AudioContext` and `navigator.getGamepads` hooks must be installed first).
  Contains the three formerly-inline blocks:
  1. AudioContext autoplay unlock (`resumeAudio` on click/keydown/touchstart);
  2. gamepad→keyboard translator with per-engine key-map presets selected via
     `window.__gamepadKeyMap`: `'rsdkv4'` (z/x/c/s, q/e, Tab/Enter, arrows —
     the exact map Sonic 1/2 already used) and `'rsdkv5'` (a/s/q/w, d/e,
     Tab/Enter, arrows — RSDKv5's default P1 keyboard binds, verified against
     `defaultKeyMaps` in `RSDKv5/RSDK/User/Core/UserCore.cpp`); a custom map
     object is also accepted. Respects `window.isDevMenuOpen()` (releases all
     held synthetic keys when a menu opens — small fix over the old Sonic 1/2
     version, which could leave keys stuck held) and skips Select/Start while
     the Select+Start menu-toggle combo is held;
  3. SDL2 gamepad proxy (unchanged behavior; dropped the Sonic 1/2 copy's
     per-second/per-press debug console.logs).
- **`scripts/sonic/index.html`**: inline blocks 1–3 replaced by
  `window.__gamepadKeyMap = 'rsdkv4'` + `<script src="/shared/game-input.js">`.
- **`scripts/sonic-mania/index.html`**: inline audio/proxy blocks replaced by
  `window.__gamepadKeyMap = 'rsdkv5'` + the same script tag. This is what
  *adds* the missing translator to Mania.
- Deployed copies synced by hand (`public/game/sonic-1|sonic-2|sonic-mania/
  index.html`), matching what the build scripts' final `cp` produces — no
  rebuild needed since only the shell HTML changed.

### Verification

Headless Chromium (Playwright) against `astro dev`, with a fake
non-"standard" gamepad injected before page scripts, for both
`/game/sonic-mania/index.html` and `/game/sonic-1/index.html`:

- proxy exposes the pad as `mapping: "standard"` compacted to index 0 —
  PASS on both pages;
- pressing pad buttons 0/1/3/9/12/15 emits keydown+keyup for a/s/w/Enter/
  ArrowUp/ArrowRight on Mania, and z/x/Enter/ArrowLeft (0/1/9/14) on
  Sonic 1 — PASS on all;
- no unexpected console errors on either page.

Not verified with physical hardware in this session; worth a quick real-pad
sanity check in the browser.
