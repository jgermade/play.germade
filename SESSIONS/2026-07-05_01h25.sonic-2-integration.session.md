# Sonic 2 Integration

## Topic: Sonic 2 via Parametrized Build Script

- **Status:** Completed
- **Created:** 2026-07-05 01:25

### Objective

Add Sonic 2 to the launcher, reusing the existing RSDKv4 WASM build infrastructure from Sonic 1.  
The key improvement is to **parametrize** `build-sonic1-docker.sh` into a single shared script `scripts/sonic/build-sonic-docker.sh` that accepts the game number (`1` or `2`) as an argument.

### Proposed Changes

1. **Unify build script** → `scripts/sonic/build-sonic-docker.sh <1|2>`
   - Accept `SONIC_NUM` as first argument (default: `1`)
   - Derive `ASSETS_DIR`, `TARGET_DIR`, `OUTPUT_NAME` from the argument
   - All patches (main.cpp, Audio.cpp, RetroEngine.cpp, Input.cpp) are identical for both games — same RSDKv4 engine
   - Copy the shared `scripts/sonic/index.html` shell (identical for both games)

2. **Move shared assets** out of `scripts/sonic1/`:
   - `scripts/sonic1/index.html` → `scripts/sonic/index.html` (shared shell)
   - `scripts/sonic1/build-sonic1-docker.sh` → `scripts/sonic/build-sonic-docker.sh` (parametrized)

3. **`settings.ini` moves to `scripts/sonic/`** (versioned in git):
   - `game-assets/sonic-1/settings.ini` → `scripts/sonic/settings-sonic-1.ini`
   - New file: `scripts/sonic/settings-sonic-2.ini` (same content, can differ per game)
   - The build script copies the appropriate one into the build directory
   - `game-assets/` only contains `Data.rsdk` (proprietary, gitignored)

4. **`game-assets/sonic-{1,2}/`**: User provides only `Data.rsdk` (gitignored).

5. **Makefile**: Add `build.sonic-2` target calling `scripts/sonic/build-sonic-docker.sh 2`.

6. **`src/data/games.ts`**: Add Sonic 2 entry pointing to `/game/sonic-2`.

7. **`public/game/sonic-2/`**: Output directory for the Sonic 2 build (parallel to `public/game/sonic-1/`).

### 2026-07-05 01:35 - OOM & TextDecoder fixes

- **First attempt** (`TOTAL_MEMORY=128MB`): OOM crash — Sonic 2's `Data.rsdk` is ~130MB.
- **Second attempt** (`ALLOW_MEMORY_GROWTH=1`): `TextDecoder` crash — newer Emscripten uses `ResizableArrayBuffer` which browser `TextDecoder` rejects.
- **Final fix**: `TOTAL_MEMORY=256MB` static, no `ALLOW_MEMORY_GROWTH`. Leaves ample headroom without the resizable buffer issue.

**Result:** ✅ Sonic 2 fully functional. Session complete.
