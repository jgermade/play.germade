## Context

Phase 2 (`2026-07-06_00h45.smw-widescreen-phase2.session.md`, capitulated
after iteration 18) ported the wide-snes game-logic checklist to runtime
C patches. What ships today: full widescreen gameplay at any ratio up to

that remains, so it can be prioritized and burned down.

## 1. Side-exit / entrance trigger positions

The only *gameplay-visible* leftover. Observed during iteration-18
verification: walking left in Yoshi's House side-exits to the map when
Mario crosses the vanilla screen edge (`player_on_screen_pos_x` wrapping
past `0xFA` in the 00e98c routine) — with the camera inset that is
~extra px *before* the visible edge, so the exit fires while Mario is
still clearly on screen. Symmetrically on the right.

- wide-snes reference: `level_side_exits.asm` (trigger repositioning)
  and `level_entrances.asm` (also covers sublevel camera placement for
  castle/ghost-house entrances).
- Phase-2 note ("Side exits/entrances: deferred as a package") flagged
  that parts depend on Lunar-Magic room data we don't have; the *trigger
  position* part looks portable without room data (same class as the
  walk-to-edge immediates) — needs a hook-by-hook review to split the
  portable subset from the room-coupled one.
- C sites: `smw_00.c` `HandlePlayerLevelColl_00E98C` (the
  `flag_side_exits` branch), `smw_05.c` LoadLevel-area entrance/camera
  placement.

## 2. Rooms/base-BPS package (real-wide title, overworld, credits)

Currently covered by the pillarbox, which is a *decision*, not a gap —
wide-snes itself ships these as fixed-width binary assets + Lunar-Magic
room edits, which cannot serve our runtime-configurable ratio:

- `title_screen.asm`: wider border stripe-image assets
  (`title-screen*.stim`, one per width), retimed demo recording, an
  edited C7 level.
- `overworld.asm`: extended scroll range, cloud spawn fixes, an
  overworld border asset.
- `credits.asm`: enemy-cast pillarbox and Yoshi's House credits fixes.
- Room-coupled boss leftovers deferred at iteration 16: Iggy/Larry lava
  stream extension ($03C0CD), Lemmy/Wendy 8th pipe ($03CC38..), Bowser
  C1 interaction fill ($009A17); plus `facing_fix.asm`.

Going real-wide here would mean generating our own width-parametric
assets at build time (e.g. synthesizing the border tilemaps) — genuinely
large effort for cosmetic screens. Recommendation: keep the pillarbox;
only revisit if a fixed default ratio is ever frozen.
