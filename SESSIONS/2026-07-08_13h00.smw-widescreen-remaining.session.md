## 2. Rooms/base-BPS package (real-wide title, overworld, credits)

Currently covered by the pillarbox, which is a *decision*, not a gap —
wide-snes itself ships these as fixed-width binary assets + Lunar-Magic
room edits, which cannot serve our runtime-configurable ratio:

- `title_screen.asm`: wider border stripe-image assets
  (`title-screen*.stim`, one per width), retimed demo recording, an
  edited C7 level.
- `overworld.asm`: extended scroll range, cloud spawn fixes, an
  overworld border asset.
- `credits.asm`: enemy-cast pillarbox and Yoshi's House credits fixes.
- Room-coupled boss leftovers deferred at iteration 16: Iggy/Larry lava
  stream extension ($03C0CD), Lemmy/Wendy 8th pipe ($03CC38..), Bowser
  C1 interaction fill ($009A17); plus `facing_fix.asm`.

Going real-wide here would mean generating our own width-parametric
assets at build time (e.g. synthesizing the border tilemaps) — genuinely
large effort for cosmetic screens. Recommendation: keep the pillarbox;
only revisit if a fixed default ratio is ever frozen.

## 2026-07-08 - §1 hook-by-hook review → iteration 19: pillarbox 1-screen rooms

User: "continúa con lo indicado en la última sesión" → §1 per the
proposed order. The hook-by-hook review §1 called for changes the plan:

**Finding: the "portable subset" of the trigger move is empty in vanilla
SMW.** `level_side_exits.asm` is a single hook widening the trigger
window from vanilla `player_on_screen_pos_x < 0xFA` (uint16 wrap ⇒
`[0, 0xFA)`) to `[-8-extra, 0xF8+extra)`. But `flag_side_exits` ($1B96)
has exactly one writer: **sprite 8C** ("side exit enabled + Yoshi's
House fireplace smoke", smw_02.c `Spr08C_SideExitAndFireplace`, 02f4d5),
and vanilla SMW places sprite 8C only in **Yoshi's House ($104) and Top
Secret Area ($003) — both 1-screen rooms** (screens == 1 in the ROM
headers, read during the Yoshi's House death fix). In 1-screen rooms our
camera model pins the camera to 0, so widening the trigger sends Mario
~extra px past the room edge **over void** (no collision data beyond the
room — the phase-2 deferral's original objection); wide-snes only
survives because its base BPS widens those rooms' floors. There is no
vanilla level where the widening is both safe and useful: multi-screen
side-exit levels don't exist. `level_entrances.asm` re-confirmed
room-coupled (redirects entrance-scene layer-1 pointers to LM-populated
level slots $030-$032): stays in the §2 rooms/base-BPS package.

**Revised fix — same goal, opposite mechanism: move the visible edge to
the trigger instead of the trigger to the visible edge.** Extend
iteration 18's per-frame pillarbox to 1-screen horizontal rooms, whose
vanilla view *is* the whole room:

1. `smw_rtl.c`: new `uint16 WidescreenLevelExtra(void)` (declared in
   `smw_rtl.h`) — 0 when `!(misc_level_layout_flags & 1) &&
   camera_last_screen_horiz == 1` (horizontal 1-screen room: no camera
   slack), else `g_widescreen_extra`.
2. The `SmwDrawPpuFrame` clamp gains `&& WidescreenLevelExtra()`:
   1-screen rooms render pillarboxed vanilla 4:3. Room shape is constant
   within the wide mode band; room-to-room transitions (doors/pipes)
   pass through fade/forced blank, so bars flip while black.
3. `HandlePlayerLevelColl_00E98C`: the three iteration-2/18 widenings
   (kill window $00E9A1, right walk bound $00E9B5, left walk bound
   $00E9C2) read `WidescreenLevelExtra()` instead of
   `g_widescreen_extra` — vanilla bounds inside 1-screen rooms (Mario
   blocked, or side-exiting, exactly at the now-visible vanilla edge),
   unchanged everywhere else.
4. The side-exit trigger itself stays vanilla (`< 0xFA`): with the room
   pillarboxed it fires exactly at the visible edge — §1's goal.

Effects beyond §1: the intro C5 wrapped-copy corner artifact (parked
since phase-2 step 1) is retired — the intro renders pillarboxed like
the title; the title demo's game logic (level C7, 1-screen) reverts to
vanilla margins, *reducing* the accepted recording-desync risk; the
iteration-16 room-coupled boss leftovers (Iggy/Larry lava stream,
Lemmy/Wendy 8th pipe, Bowser C1 fill) become moot for every arena that
is a 1-screen room (Lemmy/Wendy confirmed from the headers; Iggy/Larry/
Bowser expected — check when those scenes become reachable), since those
rooms now compose vanilla between bars. Sprite-logic sites keep the
global `g_widescreen_extra` (spawn margins/OAM MSBs in a pillarboxed
room land in the cleared margins — invisible by construction, and the
iteration-18 margin memsets run after all rendering). Trade-off,
documented: 1-screen rooms (incl. boss arenas) show honest vanilla 4:3
between bars instead of wrapped-copy fake width — consistent with the
phase-2 pillarbox decision for non-level screens. 4:3 is untouched by
construction (`WidescreenLevelExtra()` returns 0 = `g_widescreen_extra`,
and the clamp was already a no-op).

Verification plan: dry-run both orders, clang syntax pass, Docker
rebuild; 16:9 headless — Yoshi's House entered: bars measured black,
walk-left side-exits at the visible edge (the §1 symptom); intro level
pillarboxed; YI2 unchanged wide (deterministic TIME-388 scene) with the
iteration-18 walk-to-edge probe still passing; title/file-select/

### 2026-07-08 - Iteration 19 fix-up: bonus-game misalignment + bar flicker

User report (screenshot of the 1UP bonus game): the room renders
pillarboxed but off-center (~extra px: Mario overlapping the MARIO
status text, blocks left of center), and "some screens lose the wide
when loading or exiting" (bars flicker on transitions). Root causes,
both in iteration 19's room detection:

**A. The bonus game keeps its camera at `extra`.** The bonus game is
level **$000/$100** (`kLoadLevel_BonusLevelSublevelsLo`, LoadLevel_
05DBAC) — ROM header: 1 screen, horizontal, normal scroll setting.
Iteration 2's init_scroll port ($05D849) sets `mirror_current_layer
{1,2}_xpos = g_widescreen_extra` at LoadLevel, before the level number
is resolved (it cannot be room-aware there). The `$00F73F` clamp's
1-screen pin (camera→0) only executes when the scroll branch actually
runs (`v2 != 0`); additionally, during the whole load sequence
`GameMode11_LoadSublevel_0096D5` (0096d5) temporarily sets
`camera_last_screen_horiz = 32` (vanilla scroll-up-to-player trick), so
the load-time `HandleStandardLevelCameraScroll()` call clamps the
camera to `[extra, …]` with the pin unreachable. In rooms where Mario
then never crosses a scroll threshold — the bonus game: he falls in
near the center — `v2` stays 0, the pin never runs, and the camera
sits at 71: the pillarboxed window shows level x `[71, 327)`,
everything shifted with Mario overlapping the status text.
(Yoshi's House/intro/title survived because their entrances do produce
scroll deltas, so the pin fired on the first moving frame.)

**B. The clamp read `$5B/$5E` live every frame.** Those bytes are only
level-header mirrors *between* a header parse and the next room
change; two vanilla writers repurpose them mid-band:
`GameMode11_LoadSublevel_0096D5` sets `$5E = 32` during every level
load, and `InitializeMode7TilemapsAndPalettes` ($03DD7D) sets
`$5E = 0` (+ `misc_screens_in_lvl = -1`) for every mode-7 boss room —
so the live read misjudged the room during load/exit transitions (bars
flipping mid-fade, "pierden el wide al cargar o al salir") and would
have rendered mode-7 boss rooms wide (wrap garbage) instead of
pillarboxed.

**Fix (one mechanism for both): latch the room shape once per room
load.** New global `g_widescreen_level_extra` (smw_rtl.c, declared in
smw_rtl.h), assigned in `BeginLoadingLevelData` (smw_05.c, 0583ac)
immediately after `LoadLevelHeader()` — the single site where every
room's header is parsed, and (via `LoadSublevel`, 05801e) *after*
GameMode11's `$5E = 32` scroll-up-to-player call, so nothing rewrites
the camera afterwards: `(!(misc_level_layout_flags & 1) &&
camera_last_screen_horiz == 1) ? 0 : g_widescreen_extra`.
`WidescreenLevelExtra()` now returns the latch (same three player-logic
call sites + the SmwDrawPpuFrame clamp, unchanged). At the same spot,
when the latch differs from the global (wide build, 1-screen horizontal
room), `mirror_current_layer{1,2}_xpos` are reset to 0 — the vanilla
camera — before the tilemap init and sprite parse consume them; during
gameplay the `$00F73F` 1-screen pin keeps it there whenever the scroll
branch runs. Scrolling rooms and 4:3 take no write (values already
equal), so behavior there is bit-identical by construction. Latch
timing across game modes: loads happen in mode 0x11, so the latch is
correct from the 0x12 "MARIO START!" screen on, and modes 0x10-0x11
render black — no visible flicker window remains. Known corner
recorded: the latch is a C global like `g_sprite_wide_flag` — a future
save-state UI must refresh it on load (same class as the iteration-10
smoke hi-byte note).
