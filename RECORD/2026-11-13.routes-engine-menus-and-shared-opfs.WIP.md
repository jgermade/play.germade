## Architecture

```
play.germade.dev/                 the launcher (home: hero + rows)
play.germade.dev/sonic1/          a game page: rsdkv4's app, Sonic 1 data
play.germade.dev/sonic2/          same engine app, Sonic 2 data
play.germade.dev/megadrive/       a system page: the Mega Drive library → a core's app
play.germade.dev/roms/            the ROM manager (rom-manager), same origin
```

One origin = one OPFS: launcher, game pages and the ROM manager read and write the same tree.

### 1 · The engine owns its app
Each engine release ships, next to its SDK, an **app**: `<id>/<id>/app/app.js` (+ components and
assets) exporting `mount(target, host)`. The app *is* the game screen: start / load-game screen,
pause menu, options — rsdkv4's port of craft's slot cards, BlastEm's save-state menu, etc. It drives
its own SDK; the launcher never talks to the engine directly.

`host` is the only thing the launcher gives it:
- `game`: `{ slug, title, accent, art }`, `storage`: the namespace (`slug`), `assets`: thunks for the
  installed files (or the chosen ROM version), `exit()`: back to the launcher.

### 2 · One usability scheme, in engine-specs
Shared by every engine app (and the launcher), so menus feel the same whatever the engine:
- **Actions:** `up down left right accept back menu more prev next` (L/R).
- **Mapping:** gamepad A = accept, B = back, Start = menu, Y = more, LB/RB = prev/next, d-pad and left
  stick move; keyboard arrows, Enter, Escape/Backspace, Tab/V, Q/E. Select+Start = menu as well.
- **Rules:** one element always focused; focus visible as the white ring; Back always one level up and,
  at the top of a game's menus, asks before leaving; Start always opens/closes the pause menu;
  the game never receives a key or button while a menu is open; hold-to-repeat timings fixed.
- **Runtime:** a tiny `createInput()` (gamepad polling + key mapping → actions, focus helper) and the
  look tokens (focus ring, type scale, safe areas) published by `@wasm-gaming/engine-specs` — the one
  dependency every engine already has, so nothing breaks the "each repo works on its own" rule.

### 3 · The launcher builds the routes
- Vite MPA: one HTML entry per catalog item, generated from the catalog at build time
  (`/<slug>/index.html`), each a thin shell that loads the engine app from `/engines/<id>/`.
- Slugs follow the owner's form: `sonic1`, `sonic2`, `soniccd`, `sonicmania`, `celeste`,
  `megadrive`, `snes`, `neogeo`, `gba` — they are also the storage namespaces (`rsdkv4/sonic1/`).
- `/megadrive/` (systems): the full-page library (the drawer's grid, bigger) → choosing a game mounts
  the selected core's app on the same page. The home drawer stays as the quick picker.
- Service worker: each route's shell precached, COOP/COEP on every navigation (as today).

### 4 · Shared OPFS layout (a spec both apps follow)
```
library/<system>/roms/<sha1>.<ext>  +  library/<system>/index.json   (ROM manager writes, launcher reads)
<engine-id>/<namespace>/…                                             (engines: data, saves)
```
The ROM manager adopts the `library/` layout (it already groups by DAT hash); the index format is
written down in engine-specs (or a small `library-spec`) so both sides validate it.

### 5 · View Transitions
Cross-document transitions (`@view-transition { navigation: auto; }`): the tile's art morphs into the
game page's hero/stage (`view-transition-name: art-<slug>`), and back. Progressive: browsers without
support just navigate.

## Extension · 2026-11-13 — Owner: "ruta para sistema + query string para juego (+versión)(+patch)"

URL scheme for systems: the **path names the system**, the **query names what to play**:

```
/megadrive/                                            the system page: its library
/megadrive/?game=old-towers                            play the newest version
/megadrive/?game=old-towers&version=ca2c05c0           a specific version (SHA-1 prefix, ≥ 8)
/megadrive/?game=old-towers&version=ca2c05c0&patch=1f3e9a04   with a ROM-hacking patch applied on load
```

- `game` = the library's game id (also the save namespace: `<engine>/<game>/`, `<engine>/<game>+<patch>/`
  when patched); `version` and `patch` = SHA-1 prefixes, unique within the system's library.
- One static page per system (works on GitHub Pages: no server rewrites needed); the query is read
  client-side, so links are shareable and the back button returns to the library or the launcher.
- A missing or unknown `version` falls back to the newest; an unknown `game` shows the library with
  a notice.
- Open question: modern-retro games (Sonic 1/2…) — keep their own path (`/sonic1/`) as written
  earlier, or the same scheme under their engine (`/rsdkv4/?game=sonic1`).

## Extension · 2026-11-13 — Phase 2 approved ("ok, dale"): concrete design

- **Slugs** (also save namespaces and library ids): `sonic1 sonic2 soniccd sonicmania celeste`
  (own path) · `neogeo megadrive snes gba` (system path; library folder `library/<system>/`).
- **Route pages** generated by a Vite plugin from the catalog: `routes/<slug>/index.html`
  (gitignored), emitted as `/<slug>/index.html`; the dev server rewrites `/<slug>/` to it.
- **Route runtime** (`src/route/main.js`):
  - game path: not installed → the install screen on that page; installed → the engine app;
  - system path: no `game` → the library (full page, same component as the home drawer);
    `?game=…[&version=…][&patch=…]` → resolve version (SHA-1 prefix, else newest), core
    (game → console → default), assets → the engine app. `patch` is parsed and shown as "not yet".
  - **Engine app**: `import('/engines/<id>/app/app.js')`; engines don't ship one yet, so the launcher's
    **generic app** (today's player + pause menu, rewritten against `EngineApp`) is the fallback.
  - `exit()`: back in history when we came from the launcher (bfcache keeps the home as it was),
    else `/` (or `/<system>/` from a system game).
- **Input**: `@wasm-gaming/engine-specs` `createInput()` everywhere (home, library, generic app);
  the home's own input service becomes a thin wrapper over it. engine-specs 0.4.0 is not published
  yet: `ENGINE_SPECS_SRC=<dir>` aliases it to a local build (like `ENGINE_SRC_<ID>`).
- **View transitions**: `@view-transition { navigation: auto }` on every page; the navigated tile and
  the route's splash share `view-transition-name: art-<slug>`.
- **Home**: tiles and the drawer navigate (no iframe); focus restored from `?focus=<slug>`.
- **Service worker**: route shells precached; offline navigations fall back to the route's own shell.
- The iframe player (`play/`) is removed.

## Extension · 2026-11-13 — Phase 2 walkthrough (implemented)

- **engine-specs** (its own record): in game only Select+Start / Escape reach the menus
  (`createInput` delivers `menu` while suspended); plain Start stays the game's.
- **Slugs** renamed (`sonic1 … gba`), system id `megadrive`; tests check slugs are path-safe and that
  a system's id is its slug.
- **Routes**: `scripts/routes-plugin.mjs` writes `routes/<slug>/index.html` from the catalog
  (gitignored), adds them as entries, emits them as `/<slug>/index.html` (runs `enforce: 'post'`, after
  Vite's HTML plugin) and rewrites `/<slug>/` in dev.
- **Route runtime** `src/route/`: `main.js` (resolve game / install state / library / `?game` +
  `version` prefix + `patch` notice; core = game → console → default; mount the engine app from
  `engines.json` `app`, else the generic one; `exit()` via history or `/?focus=`), `Route.html`
  (bar with B Volver, splash with the shared `view-transition-name`, install, full-page library,
  app stage, notice toast), `generic-app.js` + `PauseMenu.html` (`EngineApp.mount`, input suspended
  from boot, pause menu Continue / Restart / Back), `route.css`.
- **Home**: tiles and the drawer navigate to the routes (no iframe, no install dialog at home),
  focus restored from `?focus=`, bfcache restores refresh install state and libraries, ROM counts
  loaded at start. `input.service.js` wraps `createInput()`; Vite alias `ENGINE_SPECS_SRC`.
- **View transitions**: `@view-transition { navigation: auto }` on both kinds of page; skipped
  transitions acknowledged by an inline head script.
- **Service worker**: navigation fallback per route shell; route pages precached.
- The iframe player (`play/`, `src/play/`) removed; README / STACK updated.

**Verified** (Chromium, `vite preview`, local engine builds): home → `/sonic1/` → install a pack →
engine boots in the generic app → Escape → pause menu (Continuar / Reiniciar / Volver) → Volver →
home focused on Sonic with the installed pill; drawer import (4 ROMs) → Enter →
`/megadrive/?game=final-fight-md-plus&version=fc591c64` → BlastEm runs → pause → back home;
`/megadrive/` shows the library page; an unknown `version` plays the newest with a notice.
`npm test` 12/12.
**Not verified**: the transitions themselves (headless Chromium skips them and reports "opt-in
disabled" on two history navigations — harmless, but a real-browser check is pending); gamepad paths
(no gamepad here; covered by engine-specs' unit tests).
