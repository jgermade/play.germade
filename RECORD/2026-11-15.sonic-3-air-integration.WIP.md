# Sonic 3 A.I.R. in the launcher — proposal — 2026-11-15

Status: **proposal, awaiting approval.** Follows `RECORD/2026-11-15.sonic-3-air-card.WIP.md` (the
card, `status: 'soon'`) and the July integration (`RECORD/2026-07-05.sonic-3-integration.completed.md`).

## What upstream offers (checked today, `Eukaryot/sonic3air` at b0063df, 2026-10-24)

- Latest stable: **`v26.03.28.0-stable`**; each release ships the official web build
  (`sonic3air_web_data.zip`: wasm, `loader.js` + `sonic3air.data` with the engine's data, the
  `sonic3air_web.html` shell). GPLv3.
- Web build (`Oxygen/sonic3air/build/_emscripten`): emsdk **4.0.23** (their Dockerfile), SDL2,
  WebGL (`FULL_ES2`), `FETCH` + `websocket` (update check, optional "remastered audio" download
  from their server), **no pthreads** (no SharedArrayBuffer: COOP/COEP not required; it still runs
  under the launcher's isolation, but its downloads from sonic3air.org would need CORP/CORS).
- Saves, settings and the ROM live in an **IDBFS** mount at `/sonic3air/savedata`. If
  `Sonic_Knuckles_wSonic3.bin` (4 194 304 bytes) is not there, the shell shows a file prompt.
- A game with its own menus (title, save select, options, mods), like Sonic Mania on rsdkv5.

## Proposal

**Phase 1 — `wasm-gaming/sonic3air-wasm`, wrapping the official prebuilt release** (no C++ build;
the July session took the same route and had it running):

1. **Pinned release**: the build script downloads `sonic3air_web_data.zip` of a fixed tag
   (`v26.03.28.0-stable`), checks its sha256, and ships it unchanged next to the SDK. Their own
   shell is not used (the SDK replaces it); GPLv3 notice + link to the exact upstream tag.
2. **`Sonic3AirSDK` / `Sonic3AirPlay`** on engine-specs 1.0:
   - `assets.rom` — the Sonic & Knuckles + Sonic 3 ROM, validated (size 4 194 304 + checksum),
     written into the Emscripten FS before `main()` runs: no prompt.
   - `storage.namespace` → OPFS `sonic3air/<namespace>/`: the `savedata` folder (saves, settings)
     is copied from OPFS into the FS at start and written back on pause, on `pagehide` and on close
     (the same rule as the other engines' battery RAM). IDBFS is not mounted.
   - `pause(owner)` / `resume(owner)`: `Module.pauseMainLoop()` / `resumeMainLoop()` + suspending
     its AudioContext.
   - Input: SDL2 reads `navigator.getGamepads()`, so physical pads and the engine-specs touch pad
     (Mega Drive layout: A B C + Start) play with no bridge; keyboard as upstream.
   - Its network features off by default (update check, remastered-audio download):
     `audioremaster.bin` becomes an optional asset instead.
3. **Engine app** — boot + pause (Continuar / Volver al lanzador), like rsdkv5's: the game's own
   save select stays the load-game screen; no save states (the engine has none to expose).

**Phase 2 — only if Phase 1 falls short** (e.g. a pause that does not hold, or saves that need
hooks): build from source, pinned commit + emsdk 4.0.23 image, with a small patch for those hooks.
A large C++ build: worth it only for a concrete need.

**play.germade**
- The `sonic3air` entry becomes `kind: 'game'` with `install: { rom: { file:
  'Sonic_Knuckles_wSonic3.bin', accept: ['.bin', '.md', '.gen'], validate: { bytes: 4194304 } } }`,
  like Sonic Mania's `Data.rsdk`; `engines.json` pins `sonic3air` 0.1.0; `status: 'ready'`.
- Bonus: that ROM is the Mega Drive "Sonic & Knuckles + Sonic The Hedgehog 3" lock-on dump, which
  the Mega Drive library (and ROM Manager's DAT) already identifies — the install step can offer
  "use the one in your Mega Drive library" when it is there.
