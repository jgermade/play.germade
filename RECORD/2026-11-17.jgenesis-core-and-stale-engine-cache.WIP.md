# jgenesis as a core, and engines that never update in the browser

## 2026-11-17 — Report and diagnosis

Report from the owner:

1. jgenesis does not show up in play.germade.
2. BlastEm offers no save states in its pause menu, nor graphics settings of its own.

### 1. jgenesis

- `src/lib/catalog.js` lists jgenesis as a core of Mega Drive and Super Nintendo with
  `available: false`, so the drawer shows it as "jgenesis (coming soon)", disabled.
- `src/lib/engines.json` has no `jgenesis` entry, so nothing is fetched.
- jgenesis-wasm **0.3.0 is released** with its engine app (en/es, Ajustes, save states):
  `jgenesis-wasm.tar.gz` (checked: 200, 4.7 MB) holds `jgenesis-wasm/jgenesis/` with
  `jgenesis.sdk.js`, `engine-specs.js`, `app/app.js`, `jgenesis.single.wasm` and
  `jgenesis.threaded.wasm`.
- jgenesis **needs WebGPU** (it renders with wgpu).

### 2. BlastEm's pause menu and settings

Reproduced on `vite preview` in Chromium with BlastEm 0.2.0 (the pinned version) and a test cart
built in `.tmp/`:

- **Save states are there**: the pause menu shows Continue, the four "Suspend points" slots,
  Restart, Settings, Fullscreen, Back to the launcher. The 0.2.0 release asset ships them.
- **Video settings are only "Smoothing"** (plus the shared "Keep the screen on" and "Show
  performance"). snes9x and mGBA have Image filtering + Aspect ratio (+ Crop overscan /
  Interframe blending); jgenesis has filtering, blending shader, prescaling, aspect ratio,
  borders. BlastEm really lacks them: that is an engine change, planned in blastem-wasm's
  record `2026-11-17.video-settings.WIP.md`.

**Why the owner sees no save states: the service worker serves old engines forever.**
`src/sw.js` caches `/engines/*` with `CacheFirst({ cacheName: 'engines' })` and the comment says
"their path is pinned per release". It is not: the path is `/engines/blastem/app/app.js` for every
version. A browser that played BlastEm 0.1.2 (before save states, 0.1.3) keeps that app, glue and
wasm for good; `cleanupOutdatedCaches()` only cleans the precache. The same holds for every engine
(and can mix versions: files first asked after an update come new, the rest stay old).

## Plan

### A. Engines cached per version (`src/sw.js`)

- The service worker imports `src/lib/engines.json` (and `tools.json` for `/roms/`, if it goes
  through the same route — to check) and registers one `CacheFirst` route per engine, with
  `cacheName: engines-<id>@<version>`.
- On `activate`, delete every cache named `engines*` that is not one of the current names (the
  old single `engines` cache included).
- Result: a bump of `engines.json` brings a new service worker (its bundle changes), and on
  activation the engine that changed is fetched again; the ones that did not keep playing offline.
- Fix the comment that claimed the path was versioned.

### B. jgenesis as a core

- `src/lib/engines.json`: `jgenesis` 0.3.0 — repo `wasm-gaming/jgenesis-wasm`, asset
  `jgenesis-wasm.tar.gz`, path `jgenesis-wasm/jgenesis`, entry `jgenesis.sdk.js`, app
  `app/app.js`.
- `src/lib/catalog.js`: drop `available: false` from jgenesis in Mega Drive and Super Nintendo
  (defaults stay BlastEm and Snes9x); fix the "jgenesis joins when…" comment.
- Without WebGPU (`!navigator.gpu`): the drawer shows jgenesis disabled with a short reason
  ("needs WebGPU" / "necesita WebGPU", new message in both languages) instead of letting the game
  fail at boot. A game or console that already chose jgenesis falls back to the default core in
  that browser.
- Out of scope, noted for later: Master System / Game Gear cards (jgenesis plays them, there is no
  catalog entry), and jgenesis for GBA (mGBA stays the only core).

### C. BlastEm with more video settings

After blastem-wasm releases them (its own record): bump `engines.json` to that version. Nothing
else here: the app reads the settings from the engine.

### Checks

- `npm test`, `vite build`.
- Chromium on `vite preview`:
  - with a service worker that had BlastEm cached, a bumped version is fetched again after the
    update (cache names before / after);
  - Mega Drive drawer: jgenesis selectable; a ROM boots in jgenesis' app (WebGPU in Chromium
    headless may not be there: then the disabled state with its reason is what gets checked, and
    the boot is checked where WebGPU exists);
  - BlastEm's pause menu with the slots, and save / load a slot.

## 2026-11-17 13:30 UTC — What was built and the checks

Adds: the walkthrough of A and B, and the checks.

**A. Engines cached per version** (`src/sw.js`)
- The worker imports `src/lib/engines.json` and registers one `CacheFirst` route per engine,
  `cacheName: engines-<id>@<version>`.
- On `activate` it deletes every `engines` / `engines-*` cache not in that set: the old shared
  `engines` cache goes on the first update, and a bump refetches only that engine.
- `/roms/` is precached with the shell, so it needed nothing.

**B. jgenesis as a core**
- `src/lib/engines.json`: jgenesis 0.3.0 (`jgenesis-wasm.tar.gz`, `jgenesis-wasm/jgenesis`).
- `src/lib/catalog.js`: jgenesis in Mega Drive and Super Nintendo with `needs: ['webgpu']`
  instead of `available: false`.
- `src/helpers/cores.js` (new): `resolveCores(cores, features)` marks a core unavailable with the
  missing feature; `playableCore(cores, chosen, fallback)` falls back to the default when the chosen
  core cannot run here.
- `src/route/main.js`: WebGPU is checked by asking for an adapter (`navigator.gpu` alone exists
  with no adapter behind it), only on a page with a core that needs it, with a 1 s limit. The entry's
  cores are resolved before the drawer mounts, and a ROM launches with `playableCore`.
- `src/views/RomDrawer.html`: an unavailable core says why ("needs WebGPU" / "necesita WebGPU",
  new message `drawer.needs.webgpu`) or "coming soon".

**C.** BlastEm's video settings are built in blastem-wasm (its record
`2026-11-17.video-settings.WIP.md`), not released yet: `engines.json` stays at BlastEm 0.2.0 until
then.

**Checks**
- `npm test`: 25 / 25 (3 new in `tests/cores.test.mjs`); `vite build` passes.
- In Chromium on `vite preview`:
  - **Cache**: with `engines` and `engines-blastem@0.1.2` left from before, the new worker's
    activation removes both; playing a Mega Drive ROM then caches `engines-blastem@0.2.0`.
  - **BlastEm 0.2.0** pause menu: the four slots; saving slot 1 shows "Today · 12:37".
  - **Drawer without WebGPU**: "BlastEm", "jgenesis (needs WebGPU)", disabled.
  - **Drawer with WebGPU**: jgenesis selectable; a ROM opens jgenesis' app (`jgn-app`) and its pause
    menu. The picture itself is not checked here: on SwiftShader, wgpu panics in
    `createBuffer(mappedAtCreation)` (the same as jgenesis-wasm's record notes for this sandbox).
  - **BlastEm from the local build** (blastem-wasm's branch, `ENGINE_SRC_BLASTEM`): the new video
    settings in its Ajustes, applied live; sharp pixels are sharp.
- Not verified: jgenesis drawing on a real GPU.

Suggested commit: `fix: engines cached per version in the service worker; jgenesis as a Mega Drive and SNES core`
