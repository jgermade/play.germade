# ROM manager (`/roms/`) and mods (ROM-hacking patches)

2026-11-13 · phase 4 of `2026-11-13.routes-engine-menus-and-shared-opfs.WIP.md`; patches were phase 3
of `2026-11-12.mega-drive-and-rom-library.WIP.md`. Owner: "dale al gestor de ROMs · dale una vuelta
al gestor · ¿puedes añadir el soporte para los mods?"

## Scope
A full-page manager at `/roms/` (same origin → same OPFS `library/`), with mods as first-class
items: imported, matched to the version they were made for, played on the fly, never applied in
place.

## Data (`library/<system>/`, additive to the current index)
```
roms/<sha1>.<ext>        each ROM once
patches/<sha1>.<ext>     each mod file once (.ips / .bps / .ups)
index.json               { core, games: { id: { title, core, versions: [ { …, crc32 } ] } },
                           mods: { <sha1>: { name, file, format, size, gameId|null,
                                             target: <version sha1>|null,
                                             sourceCrc, targetCrc, addedAt } } }
```
- `crc32` is added to versions on import, and lazily to old entries (BPS/UPS name their source by
  CRC32).
- Mods live at system level so an unassigned one can exist before the player says what it is for.

## Mods
- `src/services/patch.js` — pure: `crc32`, `parsePatch(bytes)` (format, source/target CRC, sizes),
  `applyPatch(rom, patch)` for **IPS** (incl. RLE and the truncate extension), **BPS** (all four
  actions; source/target/patch CRCs verified) and **UPS** (XOR; CRCs verified). Node tests with
  hand-built patches.
- **Import**: anything dropped/picked goes through one door — ROMs, mods, and `.zip`s with either
  inside. A BPS/UPS mod whose source CRC matches a version attaches to it (verified ✓). An IPS (no
  checksum), or a BPS/UPS with no match, attaches to the game open in the manager if there is one
  (marked "sin verificar"), else lands in **Mods sin asignar**, from where it is assigned to a game.
- **Play**: `/<system>/?game=…&version=…&patch=<sha1[:8]>` — the route reads the ROM, applies the
  mod in memory (target CRC verified when the format has one), hands the result to the core.
  Title "Juego · Mod"; saves in their own folder `<engine>/<game>+<patch8>/`. A failing mod shows
  the error instead of playing an unpatched ROM silently.

## The manager page (`/roms/`, jq79 + Vite, the launcher's look and input scheme)
- **Top bar**: B Volver · "Biblioteca" · search (title filter) · *Añadir* (ROMs and mods).
- **Systems rail**: Mega Drive (count); the other systems shown as "pronto".
- **Grid** of games (the drawer's tiles: art, title, badges for versions and mods).
- **Detail sheet** for the focused game (A): title, core (console/game), **Versiones** (label,
  serial, revision, size, SHA-1 / CRC32, added; *Jugar*, *Quitar*), **Mods** (name, format,
  version it applies to, ✓ verificado / sin verificar / ✗ no coincide; *Jugar con el mod*,
  *Renombrar*, *Quitar*), *Añadir mod* (drops onto the sheet attach here).
- **Mods sin asignar** strip above the grid when any: *Asignar a…* (game picker), *Quitar*.
- Totals in the footer (games, versions, mods, MB used) and storage persistence status.
- Gamepad/keyboard per engine-specs UX.md: grid spatial nav, A open/act, Y options, B back.

## Launcher touch points
- Home top bar: *Biblioteca* → `/roms/`; drawer: *Gestionar* → `/roms/?system=megadrive`.
- Drawer version dialog lists the game's mods (*Jugar con el mod*).
- Service worker precaches `/roms/` like the routes.

## Out of scope
DAT matching (No-Intro), cover art, xdelta/APS formats, exporting/backup of the library.

## Extension · 2026-11-13 — Plan: DAT identification and covers from ROM Manager's datasets (owner: "ok, dale")

Repos stay independent: nothing of rom-manager is a runtime dependency; its data and two pure
modules are taken at a pinned commit.

- **Datasets**: `scripts/fetch-datasets.mjs` (run by `npm run build`, like `fetch-engines`) reads
  rom-manager's `static/datasets/<System>/dataset.json` at a pinned commit (`src/data/datasets.json`:
  repo, commit, `system → folder`), or a local checkout with `DATASETS_SRC=<path>`, and writes a
  slim `public/datasets/<system>.json`: `roms: [[crc, size, name, boxart]]`, `covers: { title:
  { EU, US, JP } }`, `boxarts` base URL. Generated, git-ignored, cached by the service worker.
- **Naming rules**: rom-manager's `rom-grouping.ts` + `rom-regions.ts` (pure TS, no deps) vendored as
  JS in `src/vendor/rom-manager/` (transpiled once with esbuild; header names the commit), so a game
  is named and grouped exactly as ROM Manager does (`normalizeGameName`, `parseGameName`,
  `variantKey`, `regionsOf`).
- **Identification on import**: CRC32 + size against the dataset first → game id/title from the DAT
  name (`Sonic The Hedgehog`), version label = variant key (`USA+Europe`, `Japan-rev1`), regions and
  the DAT name stored on the version (`dat`). No match → the header heuristic, as today. Existing
  libraries: versions get `dat` filled lazily; game ids are not changed (their saves hang off them).
- **Covers**: one per region (EU / US / JP), picked like ROM Manager: the boxart of a version the
  player has, then the game-level map. Fetched once (CORS) and kept in OPFS
  `library/<system>/covers/<gameId>.<region>.png`; region preference EU → US → JP with an EU/US/JP
  switch in the manager's header (ROM Manager's `header-regions`). Shown in the `/roms/` card, the
  drawer tiles, the `/megadrive/` library, and handed to the engine app as `host.game.art`.

## Extension · 2026-11-13 — Walkthrough: DAT identification and covers (implemented)

- `src/data/datasets.json` (repo, pinned commit `d23406e`, systems megadrive/snes/gba) +
  `scripts/fetch-datasets.mjs` (in `npm run build`, `npm run datasets`; `DATASETS_SRC` = local
  checkout; a failed download keeps the previous file) → `public/datasets/<system>.json`
  (megadrive 3359 ROMs / 391 game-level boxart sets, ≈300 KB). Git-ignored; the service worker
  serves `/datasets/` stale-while-revalidate.
- `src/vendor/rom-manager/rom-grouping.js`, `rom-regions.js`: ROM Manager's modules transpiled with
  esbuild, header with the commit.
- `src/services/dat.service.js`: `match(system, crc, size)` (CRC32 + size, as ROM Manager), `describe`
  (title = `normalizeGameName`, key = `variantKey`, regions, video), `coversOf` (the player's own
  releases' boxes first, then the game-level map), `cover()` (region order EU/US/JP with the
  player's regions first; fetched once with CORS, kept in OPFS `library/<system>/covers/`).
- Library: import names and groups by the DAT when it knows the ROM (version label = variant key,
  `dat` stored on the version), header heuristic otherwise; old libraries get `dat` lazily, ids
  kept, DAT title adopted unless the game was renamed (`renamed`).
- UI: `/roms/` header has ROM Manager's EU/US/JP switch; the card shows the box and "EU box"
  caption, "En el catálogo" / "Fuera del catálogo", region + PAL/NTSC tags and the DAT file name
  per version; the launcher drawer / `/megadrive/` tiles show the boxes; the engine app gets the box
  as `host.game.art`.
- Found: passing a module namespace with an exported array into a jq79 component breaks jq79's
  proxy (read-only property) — the array is no longer exported from the library service.
- Verified in Chromium with zero-filled test files whose CRC32/size match DAT entries: "Sonic The
  Hedgehog" groups `USA+Europe` and `Japan+Europe+Korea` (EU/US/JP, PAL/NTSC), EU→JP→US boxes switch,
  "Columns" too; Pang stays "Fuera del catálogo" with its mod; the drawer shows the boxes; five
  boxes cached in OPFS. `npm test` 17/17.
