### 2026-07-05 - Hide the redundant corner button on Sonic 1/2

User pointed out the on-screen `#launcher-return-btn` is now redundant on Sonic 1/2 specifically, since the web Dev Menu's pre-selected first entry already covers "return to launcher". Sonic 3 (and eventually Celeste) have no such in-game menu, so they still need the visible button.

**Implemented:**
- **`public/shared/launcher-overlay.js`** — `mount()` now checks `window.__hideLauncherReturnButton` and skips appending the button/progress-ring to the DOM if set (the elements are still created in memory so the rest of the script — gamepad long-press, classList toggles — doesn't need null-checks; they just never render). Fullscreen toggle (Cmd+Enter/Alt+Enter) is unaffected either way.
- **`scripts/sonic/index.html`** — sets `window.__hideLauncherReturnButton = true` in a small script block right before the Dev Menu script (both run synchronously before the deferred shared script).

**Verified:** rebuilt Sonic 1 and 2 — `#launcher-return-btn` no longer present, but `Escape` → `Enter` (pre-selected "Return to Launcher") still navigates to `/` correctly. Confirmed Sonic 3 (no flag set) still renders the button as before. No console errors.

### 2026-07-05 - Sonic 3: Escape menu instead of the corner button

User prefers the Escape-menu pattern over the visible corner button for Sonic 3 too. Sonic 3 is a prebuilt third-party binary (no source access), so it can't get the same rich stage-select Dev Menu as Sonic 1/2 — but a minimal single-entry version needs no engine access at all, just client-side Escape interception (same technique as Sonic 1/2).

**Checked first:** loaded current Sonic 3 build, pressed Escape before making changes — it just behaved like "any key" to skip the disclaimer/intro splash (no native pause/options menu observed at that stage). Accepting the same kind of trade-off as Sonic 1/2 (claiming Escape for our own UI); not exhaustively verified against every in-game state, but no evidence of a conflicting native binding.

**Implemented — generalized `public/shared/launcher-overlay.js`** with a second mode, toggled by a new flag:
- `window.__launcherReturnViaEscMenu = true` (set by Sonic 3's build patch, alongside the existing script tag): skips the persistent corner button entirely; instead shows a minimal `#launcher-esc-menu` overlay (single "⬅ Return to Launcher (Enter)" entry, styled like Sonic 1/2's Dev Menu) toggled by `Escape` (capture-phase intercepted, same technique as Sonic 1/2). Gamepad Select+Start held together is an alias for Escape here too (replaces the old long-press-1.2s-direct-nav for this mode). Also exposes `window.isDevMenuOpen()` so this mode's own polling doesn't self-conflict.
- Existing `window.__hideLauncherReturnButton` mode (Sonic 1/2) is untouched/unaffected — the two modes are mutually exclusive per-game via which flag is set.
- `scripts/sonic3/build-sonic3-web.sh` now injects `<script>window.__launcherReturnViaEscMenu = true;</script>` right before the `launcher-overlay.js` tag instead of leaving the button as default.

**Verified:** rebuilt Sonic 3 — corner button no longer present; `Escape` opens the mini-menu (screenshot confirmed, styled consistently); `Enter` navigates to `/`; a mocked gamepad Select+Start combo also opens it. Re-verified Sonic 1 afterward (shared script was fully rewritten) — button still hidden, Escape → Dev Menu → Enter → `/` still works exactly as before, confirming the two modes don't interfere with each other. No console errors in any test.

**Not yet done:** Celeste still uses no flag (defaults to the persistent button) — decide its treatment when that wiring is picked up.
