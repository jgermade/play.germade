## Design

### ROMs belong to the system, saves belong to the engine
Two cores play the same Mega Drive ROMs, so ROMs cannot live in an engine's folder:

```
OPFS
├── library/mega-drive/            ← the launcher's, per system
│   ├── roms/<sha1>.bin            ← each file once, content-addressed
│   ├── patches/<sha1>.(ips|bps)   ← ROM-hacking patches, never applied in place
│   └── index.json                 ← games → versions → files (+ patches)
├── blastem/<game-id>/             ← BlastEm's own folder: SRAM / saves for that game
└── jgenesis/<game-id>/            ← jgenesis's own folder
```

### Grouping versions (ROM Manager's idea, minimal first cut)
- Identify each ROM from its header: console (`0x100`), overseas title (`0x150`), serial and
  revision (`0x180`, e.g. `GM 76334511-12`), plus SHA-1 of the file.
- **Game key** = normalised title (+ serial when present). Old Towers v1.1 and v1.2 → one game,
  two versions; the tile carries the iOS-style badge **2**.
- Version label = revision from the serial (`-12` → v1.2), else file name.
- Later: No-Intro/Redump DAT matching (ROM Manager) replaces the header heuristic.

### Patches on the fly
A version can carry patches. Loading = read ROM bytes → apply IPS/BPS in memory (small pure-JS
appliers, checksums verified) → hand the result to the engine as `assets.rom`. The original file
is never modified. Patched runs get their own save folder (`<game-id>+<patch-sha1>`).

### UI (the iOS 6 folder)
- The Mega Drive card opens the drawer: one tile per **game**, badge = number of versions.
- Drop ROM files on the drawer (or **Añadir ROMs** button) → hashed, identified, stored.
- Enter on a tile → plays the latest version; a long-press / `Y` opens the version picker
  (and patches).
- Core: **BlastEm** by default, **jgenesis** selectable per system in the drawer header.

## Extension · 2026-11-12 22:00 — Default Mega Drive core: the one that performs best

Owner's decision: the default core for Mega Drive/Genesis is **whichever performs best**.

That has to be measured on real hardware; this environment cannot do it fairly (jgenesis does
not even boot on the software WebGPU adapter, BlastEm runs on software GL). So:

1. **Measure, don't assume.** A benchmark page in the launcher (`/bench/?system=mega-drive`) runs
   each core in turn on the same ROM (Old Towers v1.2, Pang) for a fixed number of emulated
   frames, unthrottled where the core allows it, and reports per core:
   - emulated frames per second (headroom over 60) and p95 frame time,
   - time to first frame, wasm download size, peak memory,
   - whether it ran at all (WebGPU availability for jgenesis).
   Engines need one small addition for this: a `frame` count or `stats()` on the play session
   (proposed as an optional contract member in engine-specs, so every engine gets it).
2. **The result picks the default,** per device class if they differ (e.g. desktop vs phone);
   the drawer header keeps the manual switch.
3. **Until there are numbers:** BlastEm is the provisional default — the only core verified here,
   and it needs only WebGL, while jgenesis needs WebGPU, which not every browser that installs the
   PWA has (notably on mobile).

Open: whether the launcher should also pick per device automatically (a short silent benchmark on
first use) instead of one global default.

## Extension · 2026-11-12 22:15 — Core per console and per game; BlastEm first

Owner's decisions:
- **The player chooses the core per console and also per game.** Resolution order when a game
  starts: the game's own choice → the console's choice → the measured default (see the benchmark
  above). Stored in the launcher's library (`library/<system>/index.json` for per-game,
  a settings record for per-console). Saves stay in the chosen engine's folder
  (`blastem/<game-id>/`, `jgenesis/<game-id>/`), so switching cores never mixes save formats.
- **Order:** BlastEm now, then rsdkv3 and rsdkv5 (approved: "dale a blastem y luego a los rsdk").

## Extension · 2026-11-13 — Phase 2 approved ("sigue con la biblioteca de ROMs"): concrete design

BlastEm is on contract 1.0 (blastem-wasm 0.2.0, not released yet: local runs use
`ENGINE_SRC_BLASTEM`). Phase 2 now, with the smallest useful version picker; patches stay phase 3.

**Data** (OPFS, owned by the launcher):
- `library/<system>/roms/<sha1>.<ext>` — each file once.
- `library/<system>/index.json` — `{ core?, games: { <gameId>: { title, core?, versions: [{ sha1,
  file, name, size, serial, revision, addedAt }] } } }`. `core` at the top is the console's choice,
  per game it overrides it (owner's rule).
- Saves: `<engine>/<gameId>/` — the engine's own folder, namespace = game id.

**Identification** (`src/data/systems/mega-drive.js`, pure functions, unit-tested): header at
`0x100` (`SEGA…`), overseas title `0x150` (domestic `0x120` as fallback), serial `0x180`
(`GM 76334511-12` → revision `12`). Game key = title without trailing version markers
(`FINAL FIGHT MD+ - V0.94b+` → `final-fight-md`), so revisions and builds of one game group together;
no usable header → file name. SMD-interleaved dumps are kept but titled from the file name.

**Import**: files picked or dropped on the drawer; `.zip` archives are opened in the browser
(central directory + `DecompressionStream('deflate-raw')`, no dependency) and every ROM inside is
imported. SHA-1 via WebCrypto; duplicates are skipped. Persistent storage is requested.

**UI** (the iOS 6 drawer): header with the system, the core selector (BlastEm; jgenesis listed,
disabled until migrated) and **Añadir ROMs**; one tile per game with a red badge = number of
versions; arrows move inside the drawer, Enter plays the newest version, **Y / V / ⋯** opens the
version list (play a specific one, or remove it — saves are kept).

**Player**: `/play/?system=mega-drive&game=<gameId>&rom=<sha1>` → core = game's → console's →
catalog default; `assets.rom` is a thunk reading the ROM from the library; `storage.namespace` =
game id.

**Checks**: unit tests (header parsing, grouping, zip reader); end-to-end in Chromium with the
owner's ROMs: import `oldtowers.zip` (2 versions), `Pang_V1.00.bin`, `FFMD_095b.zip` → 3 games,
Old Towers badge 2, play → BlastEm boots in the player, SRAM lands in `blastem/<gameId>/`.
