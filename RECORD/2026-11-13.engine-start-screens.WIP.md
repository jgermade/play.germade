# Engine start screens in the player (rsdkv4 first)

2026-11-13 · owner: "para rsdkv4, me gustaría usar un menú parecido al que tiene craft, especialmente
el de carga de partida, me gusta mucho" (https://wasm-gaming.github.io/rsdkv4-wasm/craft/).

**Status:** plan, pending approval.

## What craft's launcher does
NO SAVE + four save slots. A slot with data shows the zone artwork, zone tag/act, character portrait,
the seven emeralds (owned ones lit), lives and score, and CONTINUE; an empty slot cycles the character
(Sonic, Tails, Knuckles, Sonic & Tails) and PLAY. It reads `play.game.saveSlots()`, starts with
`play.game.start(slot, player)` and runs with `config({ startMenu: 'host' })`.

## Where it should live: in the engine, not in the launcher
Everything in it is rsdkv4 knowledge (the SData.bin layout, scene → zone tables, zone art, character
portraits). Copying it into the launcher would couple the launcher to one engine — the opposite of
"every repository works on its own". So:

1. **rsdkv4-wasm ships the screen** as part of its package: `dist/rsdkv4/ui/start-screen.html`
   (a jq79 single-file component, as craft already is) + its assets (`ui/assets/…`), ported from
   craft's `GameLauncher.html` and restyled to the launcher's look (square cards, Unbounded/Inter,
   glass). The SDK advertises it: `static ui = { start: './ui/start-screen.html' }`.
2. **The player stays generic:** if the engine advertises `ui.start` and the catalog entry opts in
   (`startScreen: true`), it boots with `startMenu: 'host'`, mounts the component over the stage with
   `{ play, onAction, title }`, and hides it when the component emits `started`. Keyboard and gamepad
   go through the same action stream (←→ slot, ↑↓ character, A play, B back to the catalog).
3. **Contract:** proposed to engine-specs as an optional static `ui` map (start screen first; later
   pause/options screens), so every engine can offer its own without the launcher knowing it.

## Open points
- The component runs on the launcher's jq79 (0.7.x); craft uses 0.5.x — the port targets 0.7.
- Verifying the slot view needs a real Sonic `Data.rsdk` (+ a save); here only the empty-slot path
  can be exercised with a placeholder pack.
