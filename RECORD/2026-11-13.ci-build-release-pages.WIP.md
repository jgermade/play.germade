# CI: build, release and GitHub Pages

2026-11-13. `play.germade.dev` answers GitHub Pages' "Site not found": Pages is enabled with that
custom domain, but the repo never had a workflow, a `gh-pages` branch or a `CNAME`, so nothing was
ever deployed — and `main` cannot be served as is (the launcher is built: `npm run build` fetches
the engines' releases and ROM Manager's datasets into `dist/`).

Owner: "me gusta tener build.yml — tests + build; release.yml — manual input: version bump (major,
minor, patch), GitHub release, deploy GitHub Pages". Same shape as rsdkv4-wasm's workflows.

## build.yml
- On push to `main`, pull requests, by hand, and called by `release.yml` (`version` input).
- Node 24, `npm ci`, stamp the version when given (`npm version <x> --no-git-tag-version`),
  `npm test`, `npm run build` (engines from their pinned releases, datasets from the pinned commit).
- Checks the site's layout (home, `/roms/`, one route per catalog entry, the service worker, each
  pinned engine's SDK + `engine-specs.js` + declared app, the datasets) and uploads `dist/` as the
  `site` artifact.

## release.yml
- `workflow_dispatch`: `version` (patch / minor / major), `dry-run` (default off).
- guard (main only) → next (resolve the version from `package.json`) → build (`build.yml` with it)
  → bump (commit `vX.Y.Z` + tag, pushed) → release (GitHub Release with `play.germade.zip` of the
  site, generated notes) + pages (`configure-pages`, `upload-pages-artifact`, `deploy-pages`).
- The custom domain stays in Settings → Pages; with the GitHub Actions source no `CNAME` file is
  needed. COOP/COEP come from the service worker (Pages cannot send headers).

## Owner's one-time settings
Settings → Pages → Source: **GitHub Actions**; once the certificate is issued, **Enforce HTTPS**.
