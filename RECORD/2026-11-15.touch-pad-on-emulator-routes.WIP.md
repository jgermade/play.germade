# The touch pad on the emulator routes

2026-11-15 · owner: "Sigamos hasta dejar los mandos bien pulidos". The launcher half of engine-specs
`RECORD/2026-11-15.virtual-touch-gamepad.WIP.md` (its "Launcher work" section): engine-specs now
ships `TOUCH_LAYOUTS`, `createTouchPad()`, `exposeAsGamepad()` and `connectTouchPad()` (on its
branch, to be released as 0.5.0). Related: fbneo-wasm `RECORD/2026-11-15.gamepad-as-player-one.WIP.md`
(a pad at start is player 1 — the touch pad included).

**Status:** being implemented (the owner asked to carry on until the controls are polished).

## Plan

1. **`src/services/touch.service.js`** (new) — `attachTouchPad({ system, target, input })`:
   - only on a touch-first device (`matchMedia('(pointer: coarse)')`) and only for a system with a
     layout (`TOUCH_LAYOUTS[system]`: `megadrive`, `neogeo`, `snes`, `gba`). Elsewhere it does
     nothing — on a desktop the pad is never exposed, so FBNeo keeps player 1 on the keyboard
     (with a pad listed at start it would take player 1 from the keyboard);
   - `createTouchPad(document.body, { layout: system })`, `exposeAsGamepad(pad)` **before the
     engine starts** (SDL and FBNeo look for pads when they start), `connectTouchPad(pad, input)`
     (shown while the game has the controls, hidden in menus; its pause button opens the engine
     app's pause menu through `input.trigger('menu')`);
   - `pad.onLayout(area)` → the route's `#app` is placed in `area` (portrait: the top half;
     landscape: between the sides), back to the whole screen while the pad is hidden. The engines
     already refit their canvas when their box changes size;
   - `detach()` undoes all of it.
2. **`src/route/main.js`**: emulator routes attach the pad before mounting the engine's app, and
   detach it on exit.
3. **`src/route/route.css`**: `#app` gets `touch-action: manipulation` (no double-tap zoom on the
   game) and a short transition-free placement.
4. **engine-specs version**: the launcher reads the new exports through the package namespace and
   feature-detects them, so this branch still builds against 0.4.x (no pad) and lights up with
   0.5.0; `package.json` moves to `^0.5.0` once it is published.
