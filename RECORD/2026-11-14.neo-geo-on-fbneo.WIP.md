# Neo Geo on fbneo: a ROM library for arcade sets, and the BIOS

2026-11-14 · step 4 of the deployment order agreed with the owner (engine-specs → rsdkv5 →
rsdkv3 → fbneo). Owner: "crea los PRs". **Status: plan, awaiting approval** — unlike steps 1-3
this is a feature, not a version bump.

## Where it is
- The catalog has `neogeo` (`kind: 'emulator'`, `engine: 'fbneo'`, `status: 'soon'`), but no
  `system`, and `fbneo` is not in `engines.json`. Nothing in the launcher uses fbneo today, so
  fbneo 0.2.0 (contract 1.0; wasm-gaming/fbneo-wasm#1) breaks nothing here.
- The ROM library (`rom-library.service.js`) knows one system, Mega Drive, whose games are single
  ROM files: a `.zip` is **unpacked** and the ROM inside filed. For arcade, the zip *is* the game
  (a ROM set of many chips, matched by CRC) and must stay whole; and the BIOS (`neogeo.zip`) is
  not a game but something every Neo Geo game needs.

## What fbneo 0.2.0 gives
- `app/app.js` (blastem's app on FBNeo: suspend points, pause menu). It takes `assets.rom` (the set's
  zip) and `assets.bios` (optional, `neogeo.zip`), and **identifies the driver itself** from the
  CRC-32s inside the zip (its `romsets/*.json` datasets, shipped beside it), falling back to
  `game.slug`. A `.neo` flash-cart image is rebuilt into a set. Verified with mslug + neogeo.zip.

## Plan
1. **`src/data/systems/neo-geo.js`** — a system spec like `mega-drive.js`: `{ id: 'neogeo',
   title: 'Neo Geo', extensions: ['.zip', '.neo'], whole: true }`, and `identify(name, bytes)`:
   - `neogeo.zip` (by name or by its BIOS CRCs) → `{ bios: true }`;
   - a set → `gameId` = the FBNeo driver (matched with fbneo's `romsets/neogeo.json`, loaded from
     `/engines/fbneo/romsets/` — the copy fetch-engines already puts there), title from the dataset,
     version = the zip's SHA-1; unmatched → name-based, like Mega Drive's homebrew path.
2. **`rom-library.service.js`** — a system with `whole: true` keeps archives whole (no unpacking;
   `candidates()` yields the zip itself); the BIOS goes to `library/neogeo/bios/neogeo.zip`
   instead of the game list; `readBios(system)`.
3. **`src/route/main.js` `startRom`** — for `neogeo`, `assets: { rom, bios }` (bios read from the
   library; a missing BIOS → a clear message: "Falta la BIOS neogeo.zip: añádela a la biblioteca").
4. **Catalog / engines** — `engines.json` `fbneo` → 0.2.0, `fbneo.tar.gz`, `fbneo/fbneo`,
   `fbneo.sdk.js`, `app/app.js`; `neogeo` gets `system: 'neogeo'`, `accept: ['.zip', '.neo']`,
   `status: 'ready'`. The drawer and ROM Manager list it like Mega Drive.
5. **Tests** — `identify` (BIOS by name and by CRC, a set by CRC with a mangled file name, an
   unknown zip), whole-archive import, the BIOS kept out of the games.
6. **Verify** — built + preview, the owner's `mslug.zip`, `garou.zip` and `neogeo.zip`: import into
   the library, BIOS recognised, both games listed by their dataset titles, `/neogeo/?game=mslug`
   boots in fbneo's app; without the BIOS, the message.
